# Requerimientos — Análisis del Sistema

Corresponde a las actividades "Levantamiento de requerimientos", "Análisis de procesos actuales", "Identificación de requerimientos funcionales/no funcionales" y "Elaboración de casos de uso" del cronograma (semanas 36-39). Es el entregable "Documento de análisis y requerimientos" del Gantt.

- **[`requerimientos.md`](requerimientos.md)** — borrador de requerimientos funcionales, no funcionales y casos de uso de alto nivel, construido a partir de lo ya aprobado en el anteproyecto. Cada punto que falta por confirmar está marcado `[VALIDAR]`.
- **[`guia-validacion-asesor.md`](guia-validacion-asesor.md)** — preguntas por módulo para la reunión con Juan Alexis (asesor empresarial), pensadas para resolver justo esos `[VALIDAR]`.

## Flujo de trabajo

1. Revisar `requerimientos.md` — es el punto de partida, no la versión final.
2. Reunión con Juan Alexis usando `guia-validacion-asesor.md`, registrando las respuestas ahí mismo.
3. Regresar a `requerimientos.md` y resolver cada `[VALIDAR]` con lo que haya confirmado el asesor (quitar la etiqueta una vez resuelto).
4. Cuando ya no queden `[VALIDAR]` pendientes de decisiones importantes, este documento queda cerrado y se pasa a `docs/02-diseno/`.
